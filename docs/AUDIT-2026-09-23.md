# Full audit: code and UI (2026-09-23)

Scope: `dashboard/` (React/Vite), `supabase/` (migrations, RLS, `alert-notify`),
`firmware/` (both sketches), and `landing/`. This report lists findings and
suggested changes only. Nothing was fixed in this pass.

## How the evidence was gathered

- Read every source file in `dashboard/src`, every migration, the edge function,
  the landing page, and the risky parts of both firmware sketches (config

- Rendered the real app in headless Chromium with mocked Supabase responses
  (three devices: one tilt device with 48h of data, one hub with an open
  alert, and one offline hub) at 1280px and 375px.
- WCAG contrast was computed for every foreground/background pair flagged below.
- Not tested: real devices, Realtime, touch gestures, and the email path.

### Implementation integrity verdict: pass, with defects

The visual system is coherent and specific to this product. It uses one
instrument vocabulary (the four gauge states), a warm panel palette, SG
notation on the gravity dial, and honest empty and error states that never
pose as reassurance. The main defects are in behavior rather than style. Two
of them break the product's own first principle, "Never go silent": the live
page cannot notice that a device has died, and the analytics state machine
cannot reach its final state.

## P0: blocking

### [P0] Connection status is frozen at page load
- **Location:** `dashboard/src/pages/DeviceDetail.tsx:187`, `dashboard/src/pages/Devices.tsx:271`, `dashboard/src/lib/connection.ts`
- **Category:** Implementation integrity
- **Impact:** `getConnectionInfo(device, new Date())` only runs on render. No
  timer or `visibilitychange` handler triggers a re-render, and the Realtime
  handler appends readings without updating `device.last_seen_at`. If a
  device dies while the page is open, it keeps showing "online, 5m ago"
  indefinitely, and the "5m ago" label never advances. This contradicts
  Product Principle 1.
- **Fix:** Add a `useNow(30_000)` hook that ticks every 30s and on tab focus,
  and use it everywhere connection status is computed. In the Realtime
  reading handler, also update `last_seen_at` (`setDevice(d => ({...d, last_seen_at: row.created_at}))`).
  On `/devices`, either subscribe to `readings` inserts or re-fetch on an
  interval and on focus.

### [P0] The edge function accepts unauthenticated requests
- **Location:** `supabase/functions/alert-notify/index.ts:108`
- **Category:** Security
- **Impact:** The check is `if (WEBHOOK_SECRET) { ...check... }`, and
  `verify_jwt = false`. If the secret is unset, which is easy to miss because
  the setup has three manual steps, anyone can POST a forged `record`. The
  function then emails the real owner of any device ID, using the real device
  name, which makes it a phishing relay. It also trusts the payload body
  instead of the database.
- **Fix:** Return 500 when the secret is missing and use a constant-time
  comparison. Re-read the alert by `record.id` with the service role and use
  that row, not the posted one.

### [P0] An empty numeric field saves 0, and the firmware applies it unchecked
- **Location:** `dashboard/src/components/ThresholdForm.tsx:25-30`; `supabase/migrations/*` (no `CHECK` constraints); `firmware/*/…ino` `fetchRemoteConfig()` (tilt sketch around line 459)
- **Category:** Implementation integrity / hardware safety
- **Impact:** `Number("")` is `0`. Clearing "Sleep interval" and saving
  writes `sleep_interval_seconds = 0`. The device reads it with no bounds
  check and calls `esp_sleep_enable_timer_wakeup(0)`, so it wakes
  continuously, keeps WiFi up and drains the cell. The dashboard then computes
  every status as `offline`, because the grace period is `0 * 1.5`. The same
  applies to min/max temperature (silently set to `0`) and to the breach limit.
- **Fix:** Apply all three layers:
  1. Form: reject empty or non-finite values.
  2. Database: add `CHECK (sleep_interval_seconds between 60 and 86400)`,
     `CHECK (consecutive_breach_limit between 1 and 100)`, and
     `CHECK (temp_min_c < temp_max_c)`.
  3. Firmware: clamp remote values before using them.

### [P0] Fermentation analytics: "Complete" is unreachable and the analytics mix batches
- **Location:** `dashboard/src/lib/fermentationAnalytics.ts:134-141`, `:167-170`; `DeviceDetail.tsx:113`
- **Category:** Correctness
- **Impact:** Readings are fetched with `created_at >= now - 48h`.
  `hasFullPlateauWindow` requires `points[0].t <= latest.t - 48h`, which
  cannot be true for that window. As a result, the stage never gets past
  "Cleanup", and the guidance never says "ready for bottling". Separately,
  the rate and stage calculations use every reading in the window, including
  readings from before `fermentation_started_at`. After a "Start new batch"
  reset, the old batch's plateau pollutes the new batch's stage.
- **Fix:** Fetch history from `min(now - 48h, fermentation_started_at)`, or
  fetch a slightly wider window (for example 72h) for the analytics.
  Filter points to `t >= fermentation_started_at` before computing the rate
  and stage. Add unit tests; the module is pure and easy to test.

## P3: polish

- Device secrets are stored in plaintext. Store `sha256(secret)` and compare hashes in `verify_device_secret`.
- Admin and Settings routes ship in the main chunk. Wrap them in `lazy()` like the charts, which would cut about 60 KB from first paint for the login screen.
- The offline gauge still draws a needle pinned at the minimum, which reads as "reading at minimum". Hide the needle or park it in the bottom gap when offline.
- The label is `"TEMP"` in `Devices.tsx:296` and `"Temp"` in `DeviceDetail.tsx:240`; it renders uppercase either way, so standardize the source string.
- Focus-dim sets neighboring tiles to `opacity-50`, which drops their secondary text below AA while hovering. Use about `opacity-70` instead.
- There's no retention policy on `readings`. At 96 rows per device per day, plan for partitioning or rollups.

## Patterns and systemic issues

1. **Validation lives only in the UI.** The database has almost no `CHECK`
   constraints and the firmware trusts remote config, so any UI bug (the
   `Number("")` bug here) reaches the hardware. Put the source of truth in
   Postgres.
2. **Time is computed once per render.** Any value derived from `Date.now()`
   (connection status, "ago" labels, mute expiry, lag hours) goes stale.
   One shared clock hook fixes all of them.
3. **Colors are duplicated across three sources**: Tailwind config, inline hex
   in SVG and Recharts props, and the landing page's own CSS variables.
4. **There is no automated safety net.** Lint doesn't run, and there are no
   tests or CI. The analytics bug would have been caught by one unit test.

## What's working

- The empty, error and loading states are honest. `loadError`, `notFound` and
  "Couldn't load history" are all distinct from real emptiness, which is rare
  and valuable.
- The gauge is solid instrument work: four states distinguished by both hue
  and glow size, `aria-label` values that include direction ("above
  maximum"), reduced-motion snapping, tabular numerals, and `useId` gradient
  scoping.
- The security model is mostly sound: device RPCs with per-device secrets, a
  `security_invoker` view, RLS-scoped multi-tenancy, a rate limit designed
  around the transaction-rollback problem, an unbiased claim-code alphabet,
  and careful `REVOKE … FROM PUBLIC` hygiene.
- Recharts is lazy-loaded with fallbacks sized to each chart, so there's no
  layout shift when a chart arrives.
- The firmware reports sensor faults instead of going silent, times out the
  I2C bus, escapes SSIDs in the captive portal, and times out the portal to
  save the battery.
- The code comments explain *why*, which made this audit fast.
